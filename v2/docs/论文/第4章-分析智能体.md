# 第4章 面向变压器油中溶解气体分析智能体设计与实现

## 4.1 引言

第2、第3章已分别给出检测分级与故障类型判断的规则计算方法。按DL/T 722—2014[6]，这些判定结果最终应整理为分析报告，并据监视与试验相关要求作出后续安排。要把前两章算出的分级与判型结果用于这一过程，还需要固定的执行顺序，以及把规则结论写入报告字段的方法。

本章在此基础上研究油中溶解气体分析智能体。以固定七步工作流编排当日分析（步骤名称与顺序见图4.1）；分析意见可用大语言模型润色，分级结果与故障类型仍取自规则模块。

## 4.2 相关研究与问题分析

电力设备运维中，人工智能已由单一算法识别扩展到流程协同与知识辅助；蒲天骄等指出智能体适合将多个分析步骤串联起来[12]，变压器运维与变电故障诊断中也有相关应用讨论[32][33]。其中也有强调自主规划、由模型自行选择步骤或直接给出诊断结论的做法。本文场景下，分级结果与故障类型要能对照到行业标准条文，不宜把判定交给模型自由决定。因此，智能体仍用于串联分析步骤，但限为固定工作流编排：判定与监测建议由行业标准规则给出，大模型只润色报告文字，不改写判定结果，也不自行规划分析顺序。

结合现有系统实现和实际使用情况，仍存在以下三点不足。

分析顺序缺乏固化。一次完整分析应按固定顺序完成从检测分级到报告生成的各步。若步骤没有固定下来，而是每次临时安排先做哪一步，就容易漏做或后做该先做的环节，同一组气体数据也难以稳定汇总成同一份报告。

监测决策条件不明确。检测周期怎么定、要不要二次采样、试验建议列哪几项，都应对应到具体条件与行业标准条文。若系统只给出“缩短周期”“建议采样”一类结论，却不写清是在什么条件下、按哪一条作出的，事后就难以核对。

大模型写意见可能改掉判定结果。正式报告需要自然语言表述。若连分级结果、故障类型也交给大模型生成，写出来的结论可能和规则算的不一样；若完全不用模型，报告文字又往往生硬。

针对上述不足，本章提出以下改进：

设计固定七步工作流。按图4.1所示顺序完成当日分析，把第2、第3章的规则计算结果落成一次完整分析。未达相应门槛时，处置紧急度或故障判型可以不做，但不中断整次分析。

建立按行业标准给出的监测决策。按分级、趋势、紧急度和判型结果，输出检测周期、二次采样建议和试验清单，并写明对应条件与所依据的标准条文，便于事后核对；试验清单承接第3章给出的项目，不另给停电或检修指令。

明确规则判定与报告润色的分工。报告按DL/T 722—2014[6]格式组织，填入报告各字段；规则给出分级结果与故障类型后不再改动，大模型只润色报告文字；模型不可用或输出不合要求时，改用规则模板生成文字，并可在结论处注明所用标准依据。

## 4.3 智能体整体架构设计

智能体内部按职责分为感知、分析、决策与表达四层，这与第1、第5章的系统五层架构不是同一套划分；四层之间用固定七步工作流串起来，名称与先后顺序如图4.1所示。大语言模型不参与检测分级与故障类型计算。系统另提供分析助手：先按规则匹配用户意图，完整分析仍走同一套七步工作流；追问则基于最近一次规则结果作答，大模型只润色文字；常见标准问题按整理好的说明直接回答。主界面和助手共用同一次分析结果。助手界面和追问交互见第5章。

## 4.4 智能体工作流设计

七步名称与先后顺序见图4.1。各步输入、输出与跳过条件如下。

气体读取：读入指定监测日的七种气体浓度，作为后续各步的共同输入。

检测分级：调用第2章方法，输出当日检测分级及表2.1各项明细。

产气趋势：调用第2章总烃月环比，输出是否速率超注意、是否涨势预警。

处置紧急度：在检测分级已达注意值2或告警时，按第2章规则给出高/中/低；未达该门槛则跳过。

故障判型：在注意值2/告警或速率超注意（含涨势预警）时，调用第3章三法交叉研判；未达门槛则跳过。

监测决策：综合前面已有结果，按第4.5节规则给出检测周期、二次采样建议与试验清单；本步不跳过。

报告生成：按分析报告生成方法写入分析报告字段，大模型只润色分析意见等文字；本步不跳过。

紧急度或判型被跳过时，监测决策和报告仍照常给出，整次分析不中断。

## 4.5 基于行业标准判据的监测决策机制设计

监测决策接在检测分级、产气趋势、处置紧急度和交叉研判之后，输出检测周期、二次采样建议和其他检查性试验清单，并写明条件与行业标准条文依据；不做停电或检修指令。检测周期数字取自DL/T 1498.2—2025[7]：基线周期对应该标准附录A中A.3.1（220kV及以下≤12h），最小检测周期对应第5.5.5条多组分装置下限≤2h；二次采样对应第5.4.5条，该条不含周期数值。A.3.1的12h与第5.5.5条少组分最小检测周期≤12h同数不同义，本文按多组分演示取≤2h。主规则如表4.1所示。注意值2及以上时，二次采样按交叉研判可信度单独判断：可信度低则建议核实，否则暂不建议。试验清单一律沿用第3章给出的项目。

表4.1　监测决策主规则

| 条件 | 检测周期 | 二次采样 |
| ---- | -------- | -------- |
| 正常或注意值1，且非涨势预警、速率未超 | 按在线基线周期(≤12h) | 不需要 |
| 涨势预警（检测分级为正常或注意值1且速率超注意） | 缩短至最小检测周期（下限≤2h） | 建议二次采样验证 |
| 注意值2/告警+紧急度低 | 保持基线并加强监视(≤12h) | 按可信度分支 |
| 注意值2/告警+紧急度中 | 缩短检测周期并加强监视（建议逼近≤2h） | 按可信度分支 |
| 注意值2/告警+紧急度高 | 缩短至最小检测周期（下限≤2h） | 按可信度分支 |

表中注意值2/告警各行按处置紧急度区分检测周期。紧急度为低时，对应仅氢气相关指标超标且总烃月环比未超注意的情形，按DL/T 722—2014[6]第9.3.3条d）维持基线周期并加强监视；紧急度为中、高时，分别对应暂稳和涨势快，检测周期按表4.1缩短。

## 4.6 面向行业标准报告版式的分析报告生成方法

报告按DL/T 722—2014[6]附录G组织。前面各步算出的判定结果汇总后，写入分析意见和其他检查性试验说明，并填到报告对应栏位。设备基本信息，以及当日与此前约一周、两周、三周取样日的气体浓度一并填入；缺数据处填“—”。总烃绝对产气速率缺少油密度等参数，报告中填“—”；总烃相对产气速率写在分析意见里。报告生成后可导出为PDF。

判定结果只来自规则计算，大语言模型不得改写分级结果、故障类型、检测周期与试验项目。分析意见按“告警级别”“趋势”“处置紧急度”“故障类型”“处置建议”分区书写，默认由大语言模型按判定结果润色；未配置模型、调用失败或未通过校验时，改用规则模板，并在界面结果与运行日志中标明本次为模型生成或规则模板。

## 4.7 判据条目与角标绑定方法

分析结论需要能对到行业标准条文，使分析过程每一步都有据可依。本章为常用判据建立条目，每条有固定编号，并写明所属标准、章节与要点。七步工作流每一步记下所用条目编号，并在运行日志中展示，便于按步骤核对依据。分析报告正文只填分析意见等字段，不在报告内挂角标或另附对照表；标准依据以运行日志为准。完整对照见附录A表A1。

## 4.8 方法验证与案例分析

### 4.8.1 方案设计与判定标准

本章主要验证三件事。一是七步能否按固定顺序跑完：不到门槛的步骤应跳过，但不影响后面的监测决策和出报告。二是报告能否写全：模型不可用或润色不合要求时，改用规则模板；运行日志要写明各步所用判据条目。三是与通用大模型直接作答对照，看规则判定在标准依据和结论边界上是否更清楚（见第4.8.5节）。分析助手的界面交互放到第5章。

### 4.8.2 测试数据集设计与构建

数据与第2章合成演示时序相同，为单台连续360天监测记录；报告中的设备基本信息使用演示设备字段。

### 4.8.3 运行环境

与第2.8.3节相同。规则计算与报告模板可在本地独立完成；配置大模型服务后，报告和助手的文字润色调用外部模型接口，本文演示默认使用通义千问qwen-max。

### 4.8.4 工作流执行与报告完整性分析

选取三类监测日查看工作流执行情况，分别为2024-05-01正常日、2024-07-05告警且涨势快日，以及2025-03-21涨势预警日。与通用大模型对照另取2024-08-09，见第4.8.5节。

正常日（2024-05-01）：气体读取、检测分级与产气趋势照常完成，处置紧急度和故障判型按规则跳过；监测决策给出基线周期，不需要二次采样；报告仍可生成。未执行的步骤不会中断整次分析。

告警且涨势快日（2024-07-05）：检测分级为告警值，总烃月环比约206%/月，七步全部执行。运行日志给出分级条件、三法判型结论、可信度、检测周期和试验建议，并附所用判据条目编号；分析意见分区齐全，数值与规则判定一致。

涨势预警日（2025-03-21）：检测分级仍为正常，但总烃月环比约19.5%/月，已超注意值。此时不做处置紧急度，仍做故障判型，监测决策和报告照常给出。

另对2025-03-21强制改用规则模板生成报告，字段仍与规则判定一致，说明模型不可用或主动降级时，报告仍能生成。三类监测日都可生成报告并导出PDF。

### 4.8.5 通用大语言模型直接作答的对照分析

第4.2节已说明，故障判定应由规则给出，大语言模型只承担报告润色。为进一步说明这一选择，本节以2024-08-09监测日为例，比较本文智能体与豆包、通义千问对同一组气体的直接作答。向两模型提供当日气体浓度（μL/L）：C₂H₂为769.92，H₂为145.11，总烃为1344.57，CH₄为188.36，C₂H₄为268.98，C₂H₆为117.31，CO为119.99，CO₂为2383.24。

三方对这组数据的主要结果如表4.2所示。

表4.2　2024-08-09当日示例性对照：本章方法与豆包、通义千问直接诊断结果

| 项目 | 本章方法 | 豆包直接诊断 | 通义千问直接诊断 |
| ---- | -------- | ------------ | ---------------- |
| 检测分级 | 告警值：乙炔达告警值，总烃达注意值2，氢气达注意值1 | 乙炔、总烃严重超标 | 乙炔、总烃严重超标 |
| 趋势与紧急度 | 总烃月环比约479%/月，超过10%/月注意值，涨势快；紧急度高 | 未给出 | 未给出 |
| 故障判型 | 三比值编码为121，电弧放电兼过热 | 三比值编码为221，判为电弧放电 | 三比值编码为111，判为高温电弧放电 |
| 故障类型三法交叉 | 三比值法、大卫三角形法、特征气体法 | 未作交叉研判 | 未作交叉研判 |
| 监测决策 | 缩短至最小检测周期≤2h，暂不建议二次采样，给出10项试验清单（详见第5.4.7节智能体分析页界面） | 给出紧急/高风险等级、5项检修重点，后续按1～3天/次跟踪 | 建议立即停运，给出4项电气试验及内部检查建议 |
| 分析报告 | 生成完整分析报告，可导出PDF | 无 | 无 |

从判定依据看，通义千问引用GB/T 7252，没有具体标准名，没有办法查证，豆包依据GB/T 7252—2022《变压器油中溶解气体分析和判断导则》，在全国标准信息公共服务平台查询，没有查到GB/T 7252—2022对应文档。本文每一步判定都对应现行电力行业标准，都能查到具体条文：检测分级依据《变电设备在线监测装置技术规范　第2部分：变压器油中溶解气体在线监测装置》（DL/T 1498.2—2025），总烃月环比、故障判型和分析报告依据《变压器油中溶解气体分析和判断导则》（DL/T 722—2014），试验清单还用到《油浸式变压器（电抗器）状态评价导则》（DL/T 1685—2017）。

从结论来看，三方都识别出乙炔、总烃异常，就这一处是一样的，其他都不同。本文三比值编码是121，豆包三比值编码是221，通义千问三比值编码是111，两者都不符合DL/T 722—2014表6的编码规则，故障类型也就判错了。它们还只用三比值法一种方法下结论，没有再用大卫三角形法、特征气体法相互验证；而且直接建议停电、停运，这属于运维处置，超出了油中气体分析该给的结论，也没有算总烃月环比、没有给处置紧急度。这说明把故障判定完全交给通用大模型，结果既不稳定，也容易说过头，所以本文让规则来做判定，大模型只把报告文字写得更通顺。对话原文见附录B。

## 4.9 本章小结

本章主要处理三个问题：分析顺序不固定、监测决策条件不够清楚，以及大模型可能改写判定结果。为此，把第2、第3章规则结果接入固定七步工作流（见图4.1）；未达门槛的步骤可以跳过，整次分析不中断。监测决策按行业标准给出检测周期、二次采样和试验清单；分析报告按第4.6节版式组织，大模型只润色文字，不改规则结论，不可用时回退为规则模板。三类监测日验证表明，七步可顺序执行，报告和规则判定一致。与通用大模型直接作答的对照则表明，自由作答易混用标准、越界给出运维指令，印证了规则判定、大模型只润色的取舍。本章结果供第5章原型系统调用。
